# Claude Code 指示: LTルート図のGPS位置・表示調整とライトテーマ

## 対象

`/keio-mttakao3/` のルート概略、GPS/BLE実測、テーマ表示を改善する。作業前に `AGENTS.md`、`web/csv-visualizer/README.md`、`docs/lt/web-dashboard-requirements.md`、`assets/app.js`、`assets/style.css`、`assets/page-mttakao3.js` を読み、既存の未コミット変更を確認して上書きしない。

## 1. 高尾山口など駅ラベルの重なりを直す

- 参考画面で、高尾山口の駅名・予定時刻・方面ラベルがルート帯の端で重なっている。3駅すべてで駅名・予定時刻・方面表示が重ならず、canvas外へ切れないようレイアウトを直す。
- 左から高尾山口、明大前、新宿の順と、駅名/公式時刻表の予定値は維持する。`11:45着` 等を別々に描いて既存の「高尾方面」ラベルと重ねない。狭い画面では方面表示を短くする、上下段へ分ける等で調整する。
- ルート概略の縮尺なし・時刻表上の予定という説明を維持する。予定位置マーカーを駅名・時刻ラベルと重ねない。

## 2. 時刻表の予定位置とGPS実測位置を同じルート帯に表示

- 現在の琥珀色マーカーは時刻表から計算した「予定位置」。これとは別に、BLEライブでは最新の有効GPS位置、CSVでは選択/再生時刻のGPS位置を使い、ルート帯上に小さなムッちゃんスプライトを「GPS推定位置」として表示する。
- スプライトは既存の速度帯フレームを再利用し、現状より約1〜2段階（目安1.5〜2倍）大きくする。マーカー全体はおおむね32〜40 CSS px、キャラクター絵は24〜30 CSS pxを目安に、駅名・予定マーカーと重なりすぎない範囲で調整する。既存の大きなドラッグ可能キャラクターとの二重表示ではないことが分かるようにする。実測マーカーは速度に応じた既存フレームでもよいが、実測位置であることを常に明示する。
- ルート上の移動方向にキャラクターの顔を向ける。今回のLTデモでは新宿（右）から高尾山口（左）へ向かうので、右向き素材を水平反転して左向きにする。反転はスプライト画像だけに適用し、マーカー枠、ラベル、文字を反転させない。進行方向を判定できない場合はこの左向きを既定にする。
- 実GPS座標を、確認済みのルート経路線へ最近傍投影し、ルート帯上の進捗位置へ対応づける。これは概略図上の位置推定であり、GPSの実測座標は既存の地図へそのまま残す。ルート線の精度が不足する場合は、マーカーを偽の地点へ置かず「GPS位置をルート図に表示できません」とする。
- 既存のGPS鮮度・水平精度・ルート外判定を調べて再利用する。GPSが古い/精度不足/ルートから遠い場合は実測スプライトを表示せず、位置がない理由を表示する。トンネル内のGPS欠測では最後の位置を現在地のように動かさない。
- BLEでは実際の受信時刻に追従し、BLE受信停止時は古い値を新しい位置として動かさない。CSVではカーソル時刻より後のGPS点を使わない。予定マーカーと実測スプライトが接近/重なる場合も別形状・ラベル・縁取りで判別できるようにする。
- ルート外（例: 秋葉原の散歩データ）では予定ルートに無理にスナップしない。現GPSは地図で示し、ルート帯はGPS推定位置なし/ルート外の状態にする。

## 2-1. 通過済み区間と観測イベントのリアルタイム表示

- ルート帯上で、現在位置より通過済みの線と未通過の線を区別する。京王ライナーの新宿→高尾山口方向では、右側の新宿からGPS推定位置までを通過済みとしてグレー、現在位置から左側の高尾山口までを未通過として既存のシアンにする。現在位置のスプライトと予定位置マーカーは既存要件どおり別表示にする。
- BLEライブでは鮮度・精度・ルート近接条件を満たす最新GPS投影位置に追従し、CSVでは再生カーソル時点までのGPSで表示する。CSVを巻き戻したら線の色とピンもその時点に戻し、カーソルより後のイベントを見せない。BLE受信停止中は通過区間を進めず、時刻表上の予定だけで実測進捗を作らない。
- 観測済みのイベントがあれば、ルート上の対応位置にピンを追加し、時系列に沿って表示を蓄積する。対象例は「GPS精度低下」「GPS更新なし」「トンネル区間付近（GPS位置からの推定）」「トンネルかも？（GPS欠測と携帯網側の複数兆候）」とする。色・形・短いラベルと凡例で種類を区別する。
- ピンは観測/判定が発生した時点で初めて追加し、現在位置より先には置かない。CSV再生ではカーソルより後のピンを隠す。BLEでは同一イベントの毎秒重複を避け、状態の開始/終了や品質段階の変化を一件として扱う。イベントが解消しても履歴ピンはそのセッション内に残す。
- 位置が取れている事象は、その時点に最も近い有効GPSをルートへ投影する。GPS欠測イベントは最後の有効なルート投影位置に「GPS更新なし（位置は推定）」として置くか、位置推定の根拠がなければ地理的位置のピンを置かず時系列イベントだけ表示する。欠測位置を正確な実測地点として描かない。
- トンネルの位置データと既存の判定結果に従い、「トンネル区間付近」「トンネルかも？」を使う。GPS欠測だけでトンネルと断定せず、通信観測がない場合も tunnel pin を作らない。単なるGPS精度低下はトンネルイベントと混ぜず別ピンにする。
- ラベルが密集する場合はピンを少し縦にずらす/重なりをまとめ、クリック/タップで時刻・根拠・位置精度を見られるようにする。ピンが増えてもルート帯の高さを押し広げず、既存のワンビューを崩さない。

## 2-2. GPS未測位時もLTページの地図に京王線沿線を表示

- `/keio-mttakao3/` ではGPS点が0件でも地図パネルを空白にせず、OpenStreetMapを京王線・高尾線の新宿〜高尾山口の範囲に合わせて表示する。現在の `drawMap()` がGPS点なしで早期returnしてタイル描画を飛ばすため、LTページに限り `cfg.route.waypoints` などの既存ルート参照情報から地図の初期範囲を作る。
- GPSなしの地図では、GPS現在位置マーカー・実測軌跡・観測地点ピンを描かない。画面上部に「GPS未測位・現在位置なし」と出し、時刻表上の予定位置と混同させない。BLEのネットワーク指標やセル履歴は従来どおり表示する。
- ルート形状を地図に重ねる場合、既存の8駅ウェイポイントを結んだ線は駅間の直線的な参考線にすぎないため、必ず「路線概略（駅位置を結んだ参考線）」と表示する。実際の線路形状と誤認させない。線路に沿う正確なジオメトリを使う場合は出典を記録し、確認できない場合は正確な線路として描かない。
- 時刻表上の予定位置を地図にも表示する場合は、GPSマーカーと形・色・ラベルを分け「予定位置（時刻表）」とする。実測GPSが来たときだけGPS現在位置と実測軌跡を追加し、予定と実測を同一視しない。
- `背景地図` がオフなら現行どおり地図タイルを取得しない。OSMの帰属リンクを常時残し、タイル読込中/失敗時は状態を表示する。一般の移動モニター `/` はルート参照点がないため、GPS未測位時に適当な場所へ移動させず、現在の未測位案内を保つ。

## 3. ダーク/ライトテーマ切り替え

- 共通ヘッダーにテーマ切替を追加し、移動モニターとLTページ両方で使えるようにする。初期値は現在のダークテーマ。ユーザー選択はテーマ値のみ `localStorage` に保存し、CSV・GPS・セル情報は保存しない。
- ライトテーマでは背景、パネル、文字、罫線、ボタン、チャート軸/グリッド、選択カーソル、バッジ、フローティングキャラクターの操作部品を読みやすくする。地図タイルの色は変えず、軌跡、GPS点、トンネル帯、セル変更/予定/実測マーカーは明るい地図上でも識別できる縁取り・色を使う。
- ダーク/ライトで同じ表示データ、BLE/CSV/再生動作、一覧/詳細のレイアウトを保つ。テーマ切替でページ全体が再読み込みされたり、時刻カーソルが飛んだりしない。
- 速度スプライトの色は保持する。フローティングキャラクターが画面の重要な駅ラベル/操作を隠す場合のため、既存のたたむ・ドラッグ操作を維持し、初期位置は主要情報に重ならない配置とする。ユーザーが保存した位置を予告なくリセットしない。

## 4. 地図上の紫色帯の説明

- 現在のスクリーンショットにある紫色の太い帯と「地下化区間（資料）・概略」ラベルは、Webアプリが描画している参考オーバーレイで、OpenStreetMap標準タイルの色ではない。通常の細い鉄道線など背景タイル側の表示と区別する。
- 凡例に「紫の帯＝地下化区間（資料・駅を結んだ概略）」と表示し、OSMタイルの帰属表示は維持する。紫の帯は地下区間の正確な坑口位置でも、現在GPS位置でもないと示す。高尾区間のトンネル位置未設定はそのまま説明する。

## 受け入れ条件

1. デスクトップ幅と狭い幅で、駅名/時刻/方面ラベル、予定位置が重ならず切れない。
2. `/#debug` と `/keio-mttakao3/#debug` で、トンネルシナリオのときBLE/CSVカーソル相当のGPS位置が予定位置とは別のスプライトで動く。現状より1〜2段階大きく、デフォルトで左向き。GPSが古い/欠測/ルート外では無理に表示しない。
3. CSV再生では未来のGPS位置を表示せず、BLEライブでは受信停止時に実測マーカーが動かない。
4. 予定と実測の凡例があり、地図・ルート帯・カードの位置情報と矛盾しない。
5. ダーク/ライトの切替、選択保存、両テーマでの一覧/詳細、CSV再生、BLE状態、地図オーバーレイの視認性を確認する。
6. 紫色帯がアプリの概略オーバーレイと明記され、OSMの地図記号と混同しない。
7. 新宿→高尾山口のBLE/DEBUG/CSV再生で、進捗に合わせて右側の通過済み線がグレー、残りがシアンになり、GPS進捗が止まれば色の境界も止まる。
8. GPS精度低下・欠測・トンネル関連ピンは観測後のみ現れ、位置推定の有無と根拠を示す。CSV巻き戻しで未来ピンが消え、ピンが増えてもルート図の高さ/ワンビューが崩れない。
9. LTページでBLE/CSVのGPS点が0件でも、背景地図オンなら京王線・高尾線沿線を俯瞰するOSM地図が表示される。GPS未測位表示を保ち、実測位置/軌跡を捏造しない。トップページでは未測位時の既存挙動を保つ。
10. 実行したテストとブラウザ目視確認、未確認事項を `docs/TEST_LOG.md` に記録する。
