# Web版キャラクターをフローティング表示する実装指示

## 目的

移動モニターと Mt.TAKAO 3号LTページに、むっちゃんをモチーフにしたオリジナルの8bit風キャラクターを、Windows XP時代のイルカ型アシスタントのような画面上の相棒として表示する。現在の小さな速度カード内表示に加え、利用者が好きな位置へ動かせる大きなフローティング表示を用意する。

既存キャラクター素材と速度連動状態を再利用し、京王の公式キャラクター画像や名前・ロゴは使わない。

## 作業前

- `AGENTS.md` と `web/csv-visualizer/README.md`、`docs/lt/web-dashboard-requirements.md` を読む。
- `app.js` の `renderCharacter()`、速度状態の更新、キャラクターCanvas、2ページの初期化設定と `style.css` の一覧/詳細レイアウトを確認する。
- `git status` を確認し、作業中の変更を上書きしない。既存の速度クラス判定やCSV/BLE更新処理を変更しない。

## UIと操作

- 通常ページ `/` と `/keio-mttakao3/` の両方で利用できる共通UIにする。
- キャラクターは `position: fixed` 相当のフローティングレイヤーに置き、ヘッダー、地図、グラフ、カードより前面に表示する。画面全体を覆わないよう、十分に大きく、既存スプライトの縦横比を保って表示する（目安: PCで96〜128px程度、狭い画面では64〜80px程度。実画面で調整）。
- 初期位置は右下などデータや主要操作を避ける位置に置く。ドラッグで画面内の任意の位置へ移動できる。上端/下端/左右端から画面外へ消えないよう、viewport内に収める。
- ドラッグ領域と表示状態を分かりやすくする。ドラッグ中に地図パン、グラフ選択、ページ選択など背面の操作を誤発火させない。タッチ/ペン/マウスでPointer Eventsを使って操作できるようにする。
- キャラクターの近くに小さな「たたむ/閉じる」操作を置く。キーボード操作とフォーカス、十分なコントラスト、`aria-label` を用意する。閉じた後に再表示するボタンを画面端に残す。
- ドラッグ位置はページをまたいで維持する。保存する場合は `localStorage` に表示位置と表示/非表示状態だけを保存し、GPS/CSV/BLEのデータは保存しない。保存値が不正、古い画面サイズで範囲外、ストレージ利用不可の場合は安全な初期位置へ戻す。
- 一覧/詳細モード、CSV/BLE/DEBUG、再生/停止のいずれでも操作できる。画面サイズ変更時に位置を再クランプする。

## キャラクターの見せ方

- Android/Webで合意済みの速度帯に応じて、既存スプライトの状態を表示し続ける。新しい速度判定や車両種別の自動判定は加えない。
- 既存の小型カードは残すか、表示場所を置き換える場合は状態・GPS速度・「速度に応じた演出で、乗り物の判定ではない」という説明をフローティング表示でも確認できるようにする。
- フローティング表示はグラフや位置情報を隠しすぎない。画像の透明部分を活かし、背景は控えめにする。常時点滅・音声・派手な自動移動は加えない。
- 「任意で動かす」は利用者によるドラッグ移動を意味する。自動で画面を横切る演出は追加しない。
- 公式キャラクター「ムッちゃん」の画像や公式素材を流用せず、既存のオリジナルキャラクター素材を使う。

## 受け入れ条件

1. `/#debug` と `/keio-mttakao3/#debug` で大きなキャラクターが他のパネルより前面に表示される。
2. ドラッグで移動し、マップや背面要素が誤操作されない。画面外へ完全に隠れない。
3. たたむ/再表示ができ、位置と状態はページ再読み込み後も保たれる（保存する設定の場合）。
4. 画面幅変更、一覧/詳細切替、CSV/BLE表示切替、再生中にも重なりや配置が壊れない。
5. 既存の速度帯表示が保たれ、速度がない/stale/精度不足でも誤った移動状態を示さない。
6. 小型カードとフローティングキャラクターの表示が二重で邪魔にならず、時刻・速度・注意書きが判読できる。
7. キーボードフォーカス、ラベル、タッチ操作を確認する。
8. ブラウザの実画面でデスクトップと狭い画面を確認し、結果と未確認事項を `docs/TEST_LOG.md` に残す。
