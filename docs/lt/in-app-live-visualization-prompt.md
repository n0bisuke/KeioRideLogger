# Claude Code指示: アプリ内ライブ可視化

以下をリポジトリルートでClaude Codeに渡してください。関連TODOは[`docs/ROADMAP.md`](../ROADMAP.md)の「計測中にGPS軌跡と通信品質をアプリ内でライブ可視化する」です。

```text
Keio Ride LoggerのAndroidアプリに、計測中のGPS軌跡と通信状態・通信品質を確認できるライブ可視化領域を実装してください。

作業前にリポジトリルートのAGENTS.md、android-app/AGENTS.md、README.md、docs/DEVELOPMENT_STATUS.md、docs/ROADMAP.md、および関連するCompose画面、RecorderViewModel/UI state、GPS/Cell/Network collector、LogEvent/CSV形式を読んでください。現在のGit変更を確認し、既存のユーザー変更を上書き・巻き戻ししないでください。

## 目的

実機でデバッグ中に、GPSが取れているか、どの範囲を移動したか、在圏セル情報があるか、RSRPとHTTP応答時間がどう変わったかをアプリ画面でその場で確認できるようにします。GPS/通信の収集やCSV記録そのものは変更せず、既存のUI state・記録イベントを表示に再利用してください。

## UI要件

1. 既存の計測開始/停止、権限説明、主な状態表示を崩さないように、画面内に折りたたみ可能な「ライブ可視化」または「デバッグ表示」セクションを追加してください。
2. GPS軌跡はCompose Canvas等で端末内に描画します。`gps`イベント/既存UI stateのlat/lonから線と現在位置を示し、水平精度を円で表現してください。欠測時は線をつながず、位置が新しい/古い/受信待ちの状態を明示してください。空の位置を0,0として描かないでください。
3. 初版は外部地図タイルなしのオフラインGPS軌跡図にしてください。画面には「GPS軌跡（概略）」と表示し、道路や駅に一致する地図として装わないでください。位置座標を地図SDK、外部API、第三者サーバーへ送信しないでください。新しい地図依存ライブラリや地図タイル通信は追加しないでください。
4. 直近60秒程度の時系列グラフを表示してください。GPS速度[km/h]、在圏セルRSRP[dBm]、HTTPプローブ応答時間[ms]は単位が違うため、原則別々の小グラフにします。既存コードのどのstate/eventから値を取得するか確認し、値を人工的に補間しないでください。
5. `http_probe`の成功、HTTPエラー、timeoutをグラフ上で区別し、現在の既定ネットワーク（携帯/Wi-Fi等）と`validated`状態もテキストで表示します。画面の値が最終更新から古くなった場合はstale/更新なしと分かるようにしてください。
6. 携帯網表示では登録済みセルの電波値と周辺セルを混ぜないでください。利用可能ならRSRP/RSRQ/RSSNR等を表示し、欠損は0にせず空欄/未取得として扱います。`cell_change`がある場合だけマーカーを表示し、`baseline`は切り替わりイベントとして数えないでください。
7. GPS待ち、位置権限拒否、ネットワーク未接続、応答待ち、計測停止、グラフデータなしをそれぞれ破綻なく表示します。GPSまたはネットワークが取れなくても、他の計測とCSV保存は継続してください。
8. UI描画用の配列/履歴は直近分に制限し、CSV全行をCompose stateに保持しないでください。取得周期・CSVスキーマ・HTTP probeの頻度は変更しません。
9. 画面幅が狭くてもグラフ、凡例、状態が読めるレイアウトにしてください。色だけで状態を区別せず、ラベル・線種・記号も使ってください。

## 制約

- Kotlin + Jetpack Composeの既存構成に従い、依頼にない依存・サービス・権限・外部通信を追加しない。
- Android SDK/Gradle/ビルドは既存Docker/OrbStackコンテナ内だけで実行する。MacホストへSDK・Gradleキャッシュを置かない。
- 実機CSV、正確なGPS座標、Cell ID、ADBログをリポジトリへ追加しない。最新CSVはローカルのDownloadsにあり、コミット対象ではありません。
- CSV列やロギング頻度は変更しない。現在の収集処理にない指標をグラフ用に捏造しない。

- 実機での表示確認をしていない項目は、未確認と明記する。
```
