# Claude Code指示: アプリ内ライブ可視化

以下をリポジトリルートでClaude Codeに渡してください。関連TODOは[`docs/ROADMAP.md`](../ROADMAP.md)の「計測中にGPS軌跡と通信品質をアプリ内でライブ可視化する」です。

```text
Keio Ride LoggerのAndroidアプリに、計測中のGPS軌跡を背景地図上に表示し、通信状態・通信品質も確認できるライブ可視化領域を実装してください。

作業前にリポジトリルートのAGENTS.md、android-app/AGENTS.md、README.md、docs/DEVELOPMENT_STATUS.md、docs/ROADMAP.md、および関連するCompose画面、RecorderViewModel/UI state、GPS/Cell/Network collector、LogEvent/CSV形式を読んでください。現在のGit変更を確認し、既存のユーザー変更を上書き・巻き戻ししないでください。

## 目的

実機でデバッグ中やLTデモ中に、GPSが取れているか、どの範囲を移動したか、在圏セル情報があるか、RSRPとHTTP応答時間がどう変わったかをアプリ画面でその場で確認できるようにします。GPS/通信の収集やCSV記録そのものは変更せず、既存のUI state・記録イベントを表示に再利用してください。

## UI要件

1. 既存の計測開始/停止、権限説明、主な状態表示を崩さないように、画面内に折りたたみ可能な「ライブ可視化」または「デバッグ表示」セクションを追加してください。
2. GPS軌跡は地図上に線・現在位置・水平精度の円で表示してください。既存UI stateのlat/lonを使い、道路・駅を含む背景地図の上へ描画します。GPS点を道路や線路へスナップしたように見せず、「GPS測位軌跡（概略）」と示してください。欠測時は線をつながず、位置が新しい/古い/受信待ちの状態を明示してください。空の位置を0,0として描かないでください。
3. 地図ライブラリ・タイル提供元を選ぶ前に、現在の公式ドキュメントと利用条件を確認してください。画面表示に必要なタイルだけ取得し、アプリの連続操作や画面回転で同じタイルを不必要に再取得しないようキャッシュを尊重してください。OpenStreetMap標準タイルを使う場合は[公式利用ポリシー](https://operations.osmfoundation.org/policies/tiles/)を守り、アプリを識別するUser-Agent、HTTPキャッシュ、常時見える帰属表示を実装してください。標準タイルの一括取得やオフライン用ダウンロードはしないでください。
4. 地図タイル要求では、タイル座標とIPアドレスからおおよその表示範囲が地図提供元に伝わります。この点を画面の近くに短く説明してください。CSV全体、Cell ID、個々のGPS測位点を地図APIや別のサーバーへ送信しないでください。これは地図タイルを表示するための要求に限ります。
5. トンネル・圏外・オフライン時は背景地図の新規取得に失敗しても、既にあるタイルや背景なしのローカル軌跡表示へフォールバックします。地図取得を待つためにGPS/センサー/セル計測、画面操作、CSV保存を止めないでください。地図上に帰属表示を置き、タイル失敗時も邪魔にならない表示にしてください。
6. 直近60秒程度の時系列グラフを表示してください。GPS速度[km/h]、在圏セルRSRP[dBm]、HTTPプローブ応答時間[ms]は単位が違うため、原則別々の小グラフにします。既存コードのどのstate/eventから値を取得するか確認し、値を人工的に補間しないでください。
7. `http_probe`の成功、HTTPエラー、timeoutをグラフ上で区別し、現在の既定ネットワーク（携帯/Wi-Fi等）と`validated`状態もテキストで表示します。画面の値が最終更新から古くなった場合はstale/更新なしと分かるようにしてください。
8. 携帯網表示では登録済みセルの電波値と周辺セルを混ぜないでください。利用可能ならRSRP/RSRQ/RSSNR等を表示し、欠損は0にせず空欄/未取得として扱います。`cell_change`がある場合だけマーカーを表示し、`baseline`は切り替わりイベントとして数えないでください。
9. GPS待ち、位置権限拒否、ネットワーク未接続、応答待ち、計測停止、グラフデータなしをそれぞれ破綻なく表示します。GPSまたはネットワークが取れなくても、他の計測とCSV保存は継続してください。
10. UI描画用の配列/履歴は直近分に制限し、CSV全行をCompose stateに保持しないでください。取得周期・CSVスキーマ・HTTP probeの頻度は変更しません。
11. 画面幅が狭くても地図、グラフ、凡例、状態が読めるレイアウトにしてください。色だけで状態を区別せず、ラベル・線種・記号も使ってください。
12. 実機の縦画面確認で、地図画像が説明文や地図後の凡例に重なって見える問題が報告されています。Composeの親レイアウト、スクロール領域、Canvas/Boxの測定サイズとclipを調査し、地図の上下にある説明文・帰属表示・凡例がそれぞれ独立して読めるように修正してください。文字サイズを大きくした場合も確認します。
13. 現在の明るいOpenStreetMapタイルではGPS軌跡線が薄く、地図上で判別しにくく見えます。アプリのMaterialテーマだけを参照せず、明るいタイル上では濃い色と明るい縁取り、暗い背景または地図なしでは明るい色と暗い縁取りなど、背景に対して十分なコントラストを確保してください。軌跡線・精度円・低精度点・最新位置は色以外の記号/形でも区別してください。

## 制約

- Kotlin + Jetpack Composeの既存構成に従います。地図表示に必要な依存・インターネット権限・タイル通信は追加できますが、使う地図SDK/提供元、通信先、送信される情報をREADMEと画面表示で明記してください。加入者情報・CSV・GPS測位点を地図サービスへ送るバックエンド/APIは追加しないでください。
- Android SDK/Gradle/ビルドは既存Docker/OrbStackコンテナ内だけで実行する。MacホストへSDK・Gradleキャッシュを置かない。
- 実機CSV、正確なGPS座標、Cell ID、ADBログをリポジトリへ追加しない。最新CSVはローカルのDownloadsにあり、コミット対象ではありません。
- CSV列やロギング頻度は変更しない。現在の収集処理にない指標をグラフ用に捏造しない。
```
