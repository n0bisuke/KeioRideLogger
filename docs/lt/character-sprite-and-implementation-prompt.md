# 速度連動キャラクター素材と実装指示

## 素材

- アプリ用スプライトシート: [`glider_speed_sheet.png`](../../android-app/app/src/main/res/drawable-nodpi/glider_speed_sheet.png)
- 画像サイズ: 1774 × 887 px、透過PNG
- 配置: 4列 × 2行。左上から7コマを使用し、右下の8コマ目は空き。
- コマの順番: 停止、ゆっくり歩き、普通歩き、走る、自転車くらい、車くらい、京王ライナー高速域。
- キャラクター: ムササビを題材にしたオリジナルの8bit風グライダー。既存のムッちゃんの画像・衣装・顔・設定を複製したものではない。

スプライトシートは画像生成による初稿です。各コマの境界を等分で切り出し、Android上で7状態に使います。画像の見た目やコマ境界に問題があれば、実装前にシートを目視して調整します。右下の空きコマは描画しません。

## 速度状態の初期案

GPSの速度をm/sからkm/hへ変換し、以下の帯に分類します。値は実車CSVを見て調整する初期値です。

| 状態 | 初期速度帯 | 表示 |
|---|---:|---|
| 停止 | 0以上、1未満 km/h | 翼をたたんで座る |
| ゆっくり歩き | 1以上、3未満 km/h | 小さな一歩 |
| 普通歩き | 3以上、6未満 km/h | 歩行ポーズ |
| 走る | 6以上、15未満 km/h | 走行ポーズ |
| 自転車くらい | 15以上、30未満 km/h | 低い姿勢で滑空 |
| 車くらい | 30以上、90未満 km/h | 前傾して滑空、風の表現 |
| 京王ライナー高速域 | 90 km/h以上 | 飛膜を大きく広げた滑空 |

5000系の車両資料に記載された京王線の運転最高速度は110 km/hです。GPS速度は車両の速度計ではなく、線区や走行状況により最高速度へ達するとは限らないため、表示名は「京王ライナー高速域」とし、「実測最高速度」と誤解させないでください。[車両メーカー資料](https://www.j-trec.co.jp/company/070/07/jtr07_032-039.pdf)

速度はGPSのノイズで状態が頻繁に切り替わらないよう、数秒間の平滑化とヒステリシスを入れます。新しい位置が一定時間届かなければ速度状態を「GPS待ち/不明」にし、古い速度のままアニメーションを続けません。停止判定はGPS誤差を踏まえて実車データで調整してください。

## 他のAIへ渡す実装指示プロンプト

```text
Keio Ride Logger Androidアプリに、GPS速度に応じて表示を切り替える8bit風キャラクターを追加してください。

作業前にリポジトリルートのAGENTS.md、android-app/AGENTS.md、README.md、関連するCompose画面とGPS状態管理コードを読み、既存の構成・Docker/OrbStack開発手順に従ってください。Android SDK/Gradle/ビルドは必ず既存コンテナ内で実行し、MacホストにAndroidビルドキャッシュを作らないでください。

素材:
- android-app/app/src/main/res/drawable-nodpi/glider_speed_sheet.png
- 1774x887 pxの透過PNG。4列x2行のスプライトシートで、左上から7コマを使い、右下は空きです。
- 画像を4列x2行に等分してsrc領域を計算し、読み込み時に7コマをそれぞれ切り出してください。端数ピクセルが出ても隣コマに重ならないよう、各境界を整数演算で計算してください。
- キャラクターを左右反転せず、透過を保ち、nearest-neighbor相当のフィルタでピクセル感を維持してください。画像を引き伸ばして縦横比を崩さないでください。
- 7状態は左上から、停止、ゆっくり歩き、普通歩き、走る、自転車くらい、車くらい、京王ライナー高速域の順です。右下の空きセルを表示しないでください。

挙動:
- 既存のGPS測定とUI状態を再利用し、GPS権限、位置収集、CSVの形式や記録頻度を今回の表示機能のために変更しないでください。
- GPS速度[m/s]を3.6倍してkm/hに変換し、初期速度帯を次のようにします。
  - 0以上、1未満: 停止
  - 1以上、3未満: ゆっくり歩き
  - 3以上、6未満: 普通歩き
  - 6以上、15未満: 走る
  - 15以上、30未満: 自転車くらい
  - 30以上、90未満: 車くらい
  - 90以上: 京王ライナー高速域
- 速度帯は設定値/関数へまとめ、あとから実機CSVを見て変更しやすくしてください。各状態に短い日本語ラベルとGPS速度の数値を併記してください。
- GPS速度をそのまま使って画面をちらつかせないよう、直近の有効サンプルを使った軽い平滑化とヒステリシスを実装してください。採用した平滑化方法と切替条件をコードコメントか説明に記載してください。
- GPS値が未取得、古い、精度不足、権限拒否、トンネル等で無効になった場合は、専用の「GPS待ち/不明」表示にし、最後の速度でキャラクターが動き続けないようにしてください。0 km/hと欠測を区別してください。
- 5000系の京王線運転最高速度は車両資料上110 km/hですが、GPS値は公式速度計ではありません。「京王ライナー高速域」は速度帯の演出ラベルとして扱い、実測の最高速度や正確な列車速度と表示しないでください。
- キャラクター表示は既存の画面デザインに収め、計測値カードや開始/停止操作を邪魔しないサイズにしてください。画像が読み込めない場合でも画面がクラッシュしない代替表示を用意してください。
- 今回は新しいアニメーションフレーム、BLE、地図、外部通信、公式キャラクター素材の追加を行わないでください。

確認:
- 速度帯の境界値、0 km/h、負値/NaN、GPS未取得、GPSが古い場合をテストまたは既存テストで確認してください。
- Compose UIで各状態とGPS不明状態が表示できることを確認してください。
- ビルドと該当テストをDockerコンテナ内で実行し、実行コマンドと結果を報告してください。実機で確認していない挙動は未確認と明記してください。
- 作業前後にgit statusを確認し、実機のCSV、GPS座標、Cell ID、ADBログなどをGitへ追加しないでください。
```

## 実機で先に確かめること

1. GPS速度が屋外・乗車中にどの程度の周期と精度で更新されるか。
2. 速度帯が数秒ごとに過剰に揺れない平滑化・切替条件。
3. トンネルや測位ロストで「不明」に切り替わり、古い値を実測中のように見せないこと。
4. スプライトが暗い画面でも見え、Compose UIの他の状態表示と競合しないこと。
