# LTデモ用Webダッシュボード要件

この文書は、京王ライナーMt.TAKAO 3号で取得するネットワーク計測を、ブラウザで見せるための要件です。画面案は説明用モックであり、数値・セル候補・グラフ形状は実測値ではありません。

## 目的

乗車中にAndroid端末が計測・CSV保存を続けながら、Macのブラウザにネットワーク状態をライブ表示する。発表では「どの場所・時刻で、在圏セル・電波品質・HTTP応答がどう観測されたか」を一目で追えるようにする。

**主役はネットワーク観測:** GPSと時刻は測定を位置づけるために使い、GPS単独の地図デモにしない。

## 表示モードと接続

### ライブモード

- Android実機をBLE GATT Server、Macの対応ブラウザをWeb Bluetooth Centralとして接続する。
- ブラウザの「BLE接続」ボタンを利用者が押して接続先を選ぶ。HTTPSで動かす。
- BLEは観客向けのライブ表示経路、端末内CSVは計測データの正本とする。BLE、ブラウザ、インターネットが止まってもAndroidの計測とCSV保存は続ける。
- 接続状態、最終受信時刻、データの鮮度、sequence欠落、切断・再接続を表示する。古い値を現在値のように残さない。
- 通信はブラウザ内で表示するだけにし、受信値を外部サーバーへ転送・アップロード・永続保存しない。

### CSVモード

- 実機CSVをブラウザ内で読み込んで同じ画面に表示し、BLE失敗時の予備と事後解析に使う。
- CSVはローカルで解析し、アップロードや自動保存をしない。位置・時刻・セル識別情報を含む生CSVをリポジトリに置かない。
- ライブとCSVのどちらを見ているか常に表示する。サンプル/リプレイデータは実測と見分けられるラベルを常時出す。

## サイト構成: 移動モニターとLTデモ

トップページは散歩・ドライブなど日常の移動を記録・確認する移動モニター、`/keio-mttakao3/` は京王ライナー Mt.TAKAO 3号のLTデモとして分ける。普段の移動でも同じ計測アプリを使えるようにしつつ、専用ページではLT用の見せ場を作る。

### トップページ: 移動モニター (`/`)

- BLE接続とCSV読み込みを入口にし、散歩・ドライブなど任意の移動セッションの記録・振り返りに使えるようにする。初めて開いたときに接続手順とデータの扱いを案内する。
- 路線・駅・時刻表を前提にせず、GPS軌跡/現在位置、経過時間、距離（有効な測位点から算出できる場合）、速度、在圏ネットワーク・セル、電波品質、HTTP probe、セル変更候補と時系列を表示する。
- キャラクターの姿はGPS速度から自動で切り替える。これは「徒歩/自転車/車/ライナーの速度感」を使った演出で、GPSだけで実際の乗り物を判定したものではない。ユーザーに毎回モードを選ばせない。
- 位置が取れない屋内では地図を無理に埋めず、GPS未測位とネットワーク計測値を分けて表示する。路線名・駅名・基地局位置を推定しない。
- CSV、BLEライブ、サンプル/リプレイの表示モードと接続状態を常時区別する。初期画面にサンプル値を実測のように表示しない。
- LTデモへの明確なリンクを置き、専用ページからもトップの移動モニターへ戻れるようにする。

### Mt.TAKAO 3号ページ (`/keio-mttakao3/`)

- 添付の最新デザイン案を基準に、走行ルートとセル観測を主役にした発表用画面にする。時刻表との照合、駅名、予定/実測の表示はこのページに限る。
- 画面案にあるセルA/B/Cや観測変更候補、速度・RSRP・HTTPグラフは、実測BLE/CSVから得られた値だけを実データとして描く。サンプルデータを使う場合は全画面でサンプルと明示する。
- 汎用モニターとBLE/CSV接続、ペイロード解釈、グラフ、地図の処理を共有する。ページごとに別の計測値や接続状態を持たない。
- 予定ルート・時刻は文書記載の情報であり、GPS実測軌跡や駅通過の実測と明確に区別する。予定と実測のずれを隠さない。

### 共通実装方針

- 画面の違いはページ設定（ページタイトル、路線/時刻表の有無、説明文、レイアウト）で表し、BLE受信・CSV解析・時系列データモデルは共通化する。
- GitHub Pagesのプロジェクトサイト配下で動く相対パスを使い、トップと`/keio-mttakao3/`の直リンク・再読み込みの両方を成立させる。
- BLE/CSVのデータ取り扱い、地図タイルの外部通信説明、鮮度表示、欠測・セル変更候補の意味は両ページで一貫させる。
- AndroidアプリとWebのキャラクター状態は、同じ速度帯・平滑化・ヒステリシス・GPS鮮度条件を使う。見た目の状態がデータ経路によって食い違わないようにする。

### 速度連動キャラクター（Android/Web共通）

- Androidアプリは既存の `SpeedClassifier` による速度帯切り替えを継続する。現在の帯は停止 `[0,1)`、ゆっくり歩き `[1,3)`、普通歩き `[3,6)`、走る `[6,15)`、自転車くらい `[15,30)`、車くらい `[30,90)`、京王ライナー高速域 `[90,∞)` km/h。
- 60 km/hは「車くらい」の帯に含める。市街地車速の目安だけで車の上限を決めない。高速道路の車と列車の速度は重なるため、「京王ライナー高速域」は乗り物の自動判定ではなく、速度に応じたキャラクター演出ラベルとする。
- WebもBLEライブとCSV読み込みの両方で同じ7段階を自動表示する。BLEに速度帯を含める場合はAndroidの判定結果を使い、CSVモードでは同じ条件で再計算する。速度帯を含めないBLE形式ならWeb側の平滑化・境界判定をAndroidと一致させる。
- 初期条件はAndroid既存実装に合わせる: 直近5秒の有効速度の中央値、境界から `max(0.5 km/h, 10%)` のヒステリシス、水平精度30m以内、GPS最終更新から5秒以内。GPS精度不足・未取得・古いデータ・速度欠測では状態を「GPS待ち/不明」にし、0 km/hや以前の姿を出し続けない。
- 速度数値と状態名を一緒に表示する。速度帯の境界や「高速域」の定義はコード/データモデルで共有し、画面ごとに別の閾値を持たない。
- キャラクターはオリジナルのムササビ素材を使い、計測データ・セル履歴・グラフの読みやすさを優先する。動きの切り替えを基地局や交通手段の認識結果と表現しない。

## 画面構成

### 1. ヘッダー

- タイトル: `Mt.TAKAO 3号｜ネットワーク観測`
- モードと状態: `BLE接続中/未接続`、`CSV再生/ライブ`、`CSV記録中`（Androidから状態を受け取る場合のみ）
- 現在時刻をJSTで表示し、タイムゾーンを明示する。
- デモデータでは、ヘッダー近くに常時 `画面案・サンプルデータ` または `サンプル/リプレイ` と表示する。

### 2. 走行ルートとセル観測

- ルートは左から右へ `新宿 → 明大前 → 高尾山口` の概略図として表示する。
- **概略図は距離縮尺なし。** 「ルート概略・縮尺なし」と明記し、距離のスケールバーを表示しない。3駅を均等配置してもよい。
- 予定時刻を駅名と一緒に表示: 新宿11:00発、明大前11:06、高尾山口11:45着。
- GPS位置を動く現在位置として示し、水平精度を円または数値で表す。GPS欠測中は最後の位置を現在位置として動かさず、古い値と表示する。
- CSV/ライブでGPS点がある場合は、実測軌跡を地図上に描く。京王線路や欠測区間を補間して実測のように描かない。地図タイルがないときは、実地理図と誤認しない「ルート概略・縮尺なし」表示へ切り替える。
- 在圏セルが観測できた区間は `セルA/B/C` などのセッション内匿名ラベルで色分けする。PCIやCell IDの生値を画面の主役にしない。
- 周辺セルの観測は在圏セルの区間と分ける。セル変更候補はひし形・破線などで示し、「観測変更候補」とラベルする。最初のセルはbaselineとして変更に数えない。
- 基地局の位置を照合できていない間は、地図に基地局ピンやセルのカバー範囲を描かない。公開データから位置候補を得た場合は、出典・更新日・推定/未確認の状態を示し、実際の接続先や電波到達範囲と断定しない。
- 楽天モバイル公式エリアマップは別の「エリア概況」資料として扱う。駅ピンは高尾山口駅であって基地局ではなく、公式エリア色は乗車中の実測品質ではない。地図画像をリポジトリへ複製しない。

### 3. 現在のネットワーク指標カード

値が新鮮な場合に限り、次を表示する。

- 移動速度: GPS推定値（km/h）とGPS最終更新時刻/水平精度。
- 在圏セル: RAT（LTE/NR等）、匿名セル名、最終観測時刻。取得不能は `データなし` とする。
- 電波品質: RSRP（dBm）。取得できる場合はRSRQ、RSSNR/SINRを別の項目として表示する。
- Androidの既定ネットワーク: 携帯網/Wi-Fi等、`validated`状態。
- 最後のHTTPプローブ: 結果、応答時間（ms）、HTTPステータス、測定時の経路。
- 速度・RSRP・HTTP応答時間をひとつのスコアに混ぜない。
- 直近のセル変更履歴を別枠に表示し、時刻、匿名化した前後セル、観測ソース/確度を示す。baseline、候補、判定不能を区別し、候補を確定handoverと呼ばない。

## 時刻表との照合

京王電鉄公式ページのMt.TAKAO 3号は土休日運行。公式掲載時刻は新宿11:00発、明大前11:06、高尾山口11:45着。乗車日当日に運行日・時刻・臨時変更を確認する（[公式時刻表](https://www.keio.co.jp/zasekishitei/index_mt.html)）。

- CSVのUTC `time_utc`はJSTへ変換して時刻表と比較する。端末時刻・記録時刻・表示時刻のタイムゾーンを混在させない。
- 予定イベントは `予定`、GPSで確認またはユーザーが記録したイベントは `実測` と明確に分ける。
- 自動判定できない乗車開始・駅通過/到着は、ユーザー操作で時刻マーカーを追加できるようにする。
- 公式に個別時刻が掲載されていない駅の時刻を推測して表示しない。

## 時系列グラフ

- 全グラフは同じJST時間軸を共有し、選択カーソルや予定マーカーを連動させる。
- 予定時刻線は新宿11:00、明大前11:06、高尾山口11:45に配置する。11:00から11:06までの6分と、11:06から11:45までの39分の幅を、時間軸上で正確な比率にする。
- RSRPはdBm、RSRQ/SINRはdB、HTTP応答はmsとして、異なる単位を別パネルに表示する。単一の共通Y軸へ重ねない。
- 欠測区間は線を切り、ゼロ値で補わない。取得時刻が異なる値同士を同時刻のサンプルのように補間・結合しない。
- HTTPプローブは成功・HTTPエラー・タイムアウトを形状やラベルでも区別する。HTTP応答時間はDNS/TCP/TLS/HTTPを含む総所要時間で、無線区間だけの遅延やpingとは呼ばない。
- BLEの最終受信遅延とHTTPプローブ応答時間は、別々の指標として扱う。
- セル変更候補があれば時刻線を引き、セル名を示す。HTTP遅延と同時に起きても因果関係を示す表現にしない。
- 時間帯フィルターとイベント選択をルート図・各グラフ・セル履歴の間で連動させる。
- CSVモードでは既存の時間範囲スライダー、軌跡、グラフ、選択時刻の同期を維持する。

## 表現・デザイン

- ダークテーマ、発表会場で読める大きさとコントラスト。PC横長画面を主対象にし、スマートフォン幅でも最低限の確認ができる。
- 色だけで区別せず、凡例、文字、線種、点形状を併用する。
- 色の役割を固定する: GPS/ルート、セルA/B/C、RSRP、HTTP応答、セル変更候補。
- モックやデモデータは実測と混ぜず、画面全体で仮データと分かる表示にする。
- 楽天モバイル、京王電鉄のロゴや公式キャラクター、許可のない公式地図画像を新規に組み込まない。
- 外部地図タイルや外部APIが止まっても、ルート概略図・数値・グラフは動作する。LTE/インターネットをライブデータ伝送経路にしない。

### 背景地図タイルを使う場合

- GPS実測軌跡の背景にOpenStreetMap標準タイルを使う場合、地図上に「© OpenStreetMap contributors」のリンクを常時表示し、[タイル利用ポリシー](https://operations.osmfoundation.org/policies/tiles/)に従う。
- タイル提供元に利用者のIPアドレスと表示範囲を示すタイル座標が伝わることを画面に説明し、地図をオフにできるようにする。
- CSV本体、Cell ID、個々のGPS測位点を地図提供元やサーバーへ送らない。ジオコーディング、経路検索、クラウド解析を追加しない。
- タイル取得失敗やオフライン時もGPS軌跡・グラフ・CSV解析を続ける。ライブデモはネットワーク接続に依存しないルート概略へ切り替えられること。

## 正確さ・データの取り扱い

- `registered=true`を在圏セル、`registered=false`を周辺セルとして扱う。
- Android APIのセル更新は制限され、すべての切り替わりを記録できる保証はない。「観測変更候補」はハンドオーバー確定と説明しない。
- MCC/MNCは現在のCSVにない。基地局照合に使う場合は取得・記録の追加を別タスクで行い、未対応中はキャリアやセル位置を推測しない。
- Cell ID、正確なGPS、正確な乗車時刻は機微な移動データとして扱い、ログ・公開サンプル・外部送信に含めない。
- OpenCelliD等の照合結果を使う場合は、APIキーをクライアントへ埋め込まず、出典・ライセンス・精度・データ更新時点を確認する。ライブ中に位置やセル情報を第三者APIへ送らない。

## 実装順と受け入れ条件

1. まず既存CSVビューアのレイアウトを整え、CSVをローカル解析する。時間範囲スライダー、軌跡、カード、セル履歴、グラフの選択同期を維持する。
2. 背景地図を使う場合はOpenStreetMapの帰属・タイル利用条件・外部送信の説明・オフライン時の挙動を確認する。
3. 実測CSVを使って時刻表マーカー、セル履歴、指標の欠測・鮮度を確認する。生CSVは公開サンプルとして追加しない。
4. BLE受信値を既存の表示モデルへつなぎ、CSVモードとライブモードで同じ見た目・指標定義を使う。
5. Android実機からGPS、在圏セル、RSRP、ネットワーク状態、HTTPプローブを受信して、画面とグラフが更新される。
6. BLEを切断してもAndroid側のCSVイベント数が増え続け、Webは切断/古い値を表示する。再接続後に新しい値から更新を再開する。
7. 時刻表マーカーの相対間隔が正確で、予定と実測が混同されない。GPS欠測、セル情報なし、probe timeout、BLE stale時は空欄/状態表示になる。
8. 外部通信を切ってもBLEの受信値と軌跡概略・グラフを表示できる。地図背景がなくてもデモが成立する。
9. 発表用ChromeでBLE接続を実機確認し、CSVフォールバックもリハーサルする。未確認項目は「実機未確認」と明記する。
10. `/`に散歩・ドライブなどの移動モニター、`/keio-mttakao3/`にLT専用画面を用意し、共通のBLE/CSVデータで両方が更新される。GitHub Pagesのプロジェクトサイト配下からそれぞれ直に開ける。
11. AndroidとWebで同じGPS速度を使ったとき、BLEライブとCSV再生のキャラクター帯が同じになる。停止、60 km/h、90 km/h境界前後、GPS stale/accuracy不足を確認し、Web側でも状態がちらついたり古い状態を維持したりしない。
