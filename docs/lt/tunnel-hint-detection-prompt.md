# Claude Code 指示: トンネル区間のヒント表示

## 目的

`/keio-mttakao3/` で、京王ライナーの予定ルート上のトンネル付近に来たとき、GPSと携帯網の観測状態を手掛かりに「トンネル区間付近」「トンネルかも？」を表示する。トンネル進入や電波遮断をセンサー値だけから断定しない。CSV再生でも当日のライブでも同じ時系列上で振り返れるようにする。

## 作業前確認

- `AGENTS.md`、`docs/lt/web-dashboard-requirements.md`、`web/csv-visualizer/README.md`、`web/csv-visualizer/assets/page-mttakao3.js`、`assets/core.js`、`assets/app.js` を読む。
- 現在のGPS鮮度、位置精度、在圏セル更新、RSRP/RSRQ/SINR、既定ネットワーク、HTTPプローブのデータ定義と鮮度判定を確認する。既存値の意味やCSV/BLE形式を推測で変えない。
- `git status` を確認し、既存の編集を上書きしない。AndroidアプリやBLEペイロード変更は、今回のUI実現に不可欠で仕様確認ができる場合以外は行わない。

## 区間データ

- 初期対象は、京王線の調布付近の地下化区間、および高尾〜高尾山口間で資料上確認できるトンネル。
- トンネルの入口/出口または経路ポリラインは、公開地図・工事資料など複数の参照情報を確認して設定する。区間名、出典URL、確認日、位置の不確かさを設定データに記録する。
- 調布地下化区間の参考: [鹿島建設の調布駅付近連続立体交差事業](https://www.kajima.co.jp/tech/c_projects/ex/2013kochfe/index.html)、携帯サービスが提供される地下トンネル区間の参考: [2012年の事業者発表](https://www.kddi.com/corporate/news_release/2012/0816/)。高尾第一トンネルの存在確認の参考: [京王電鉄の安全報告](https://www.keio.co.jp/assets/pdf/train/safety/security_feature/keio_2009.pdf)。これらは正確な境界座標や現在の各社電波品質を保証する資料ではない。
- 境界座標を信頼できる形で確定できない場合は、座標を作り話で登録しない。手動メモによる記録を残し、自動検出は「未設定」と表示する。
- 地図のGPS点を線路やトンネルへスナップしない。予定ルート概略図と実測GPS地図を混同しない。近くを歩く場合もあり得るので、乗車中/列車内と判定しない。

## 状態と表現

証拠を一つの「トンネル判定」にまとめず、位置の見込みと通信状態を分けて示す。

1. **トンネル区間付近**: 鮮度のあるGPS位置が登録済み区間の許容範囲内にある。精度円/水平精度を考慮し、境界にかかるか低精度なら「トンネル区間付近（GPS精度低下）」とする。トンネル内にいる確定表示にしない。
2. **トンネルかも？**: 直前まで区間入口付近にいたGPSが鮮度切れ/欠測となり、同時刻に携帯網の観測値も取得できない、または既存の観測値から品質低下が見える場合に限り候補表示する。理由を「GPS更新なし」「在圏セル更新なし」「RSRP取得なし/低下」「HTTP失敗」など観測事実として併記する。
3. **GPS/通信の状態は別表示**: GPS欠測だけでトンネルとしない。携帯網の値が来ないだけでもトンネルとしない。在圏セルポーリング間隔の制限、権限、モデム/API制約、屋内、端末の置き場所など他の原因がある。位置履歴がなく、区間に接近した根拠もなければ「トンネルかも？」は出さない。
4. **電波がないと断定しない**: 「電波なし」「圏外」と表示するのは既存データがその状態を明確に表す場合だけ。RSRP/RSRQ/SINRがnull、在圏セル更新なし、HTTPタイムアウト、Androidのvalidated状態はそれぞれ意味が異なるため別々に表す。HTTP失敗を無線断絶と呼ばない。RSRPに独自の絶対閾値を勝手に設定しない。
5. **区間通過後**: GPS測位が再開したら「GPS測位復帰」を時刻付きで示せる。電波/HTTPの回復は各メトリクスの実観測としてグラフで示し、トンネル通過が原因と断定しない。

## UI

- `/keio-mttakao3/` のGPS地図に、確認済みのトンネル区間を「トンネル区間（参考）」として重ねる。現在状態は「付近」「かも？」「区間外/判定材料なし」を過度に場所を取らないバナー/チップで示す。
- 通信品質グラフとセル変更グラフにはトンネル候補区間を薄い帯で重ね、入口/出口の時刻が実測できた場合だけ実測境界として記録する。位置から推定した境界は「推定」と明記し、計測値自体を変えない。
- GPS欠測区間は従来どおり線をつながない。過去の最後の位置は古い値として表示し、地図上で現在地を偽装しない。
- 現在の「実測メモ: トンネル」は残してよい。手動マーカーは予測/自動検出と別の見た目・凡例にし、選択時刻とラベルを記録する。
- 一覧ワンビューを壊さず、詳細モードでも状態の根拠と時間変化を追える。既存のカード、グラフ、セル履歴、再生機能を維持する。

## デバッグと確認

- `/keio-mttakao3/#debug` で、区間へ接近→候補区間付近→GPS/通信状態の変化→測位復帰という架空シナリオを確認できるようにする。架空のGPS軌跡・電波イベントはDEBUG表示を維持し、実測値と混ぜない。
- 通常の `/#debug`、`#demo`、実測CSVの内容を不用意に変更しない。実測CSVにトンネルを示すラベルがない場合、過去データをトンネル走行として装わない。
- CSV再生スライダーを動かし、状態バナー・地図のカーソル・RSRP/RSRQ/SINR・HTTP・セル履歴が同じ時刻に揃うことを確認する。
- ライブでBLE受信が古くなった場合とCSVの欠測を区別する。サンプル時刻の改変や、欠測を0埋めする処理を入れない。

## 受け入れ条件

1. トンネル境界の出典と精度が追跡でき、未確認の座標を捏造しない。
2. GPS位置の近接表示とGPS/携帯網/HTTPの状態が別の根拠として表示される。
3. GPS欠測だけ、HTTPタイムアウトだけ、セル更新なしだけではトンネル進入や圏外を断定しない。
4. 調布地下化区間と高尾線トンネル候補を地図で見分けられる。地図は参考範囲で、実測GPSをスナップしない。
5. CSV再生とBLEライブで、利用可能な測定値に応じて表示が更新される。取得していない値を作らない。
6. `#debug` の架空シナリオで状態の遷移と理由を確認できる。
7. デスクトップ一覧モードのワンビュー、詳細モード、通常ページ、セル履歴スクロール、再生操作に回帰がない。
8. ブラウザ確認、関連テスト、未確認事項を `docs/TEST_LOG.md` に記録する。

## 完了報告

変更ファイル、区間データの出典と精度、どの観測事実で各表示に遷移するか、CSV/DEBUG/BLEでの確認結果、断定できない制約と未確認事項を報告する。
