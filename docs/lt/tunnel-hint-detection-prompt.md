# Claude Code 指示: トンネル区間のヒント表示

## 目的

`/keio-mttakao3/` で、京王ライナーの予定ルート上のトンネル付近に来たとき、GPSと携帯網の観測状態を手掛かりに「トンネル区間付近」「トンネルかも？」を表示する。トンネル進入や電波遮断をセンサー値だけから断定しない。CSV再生でも当日のライブでも同じ時系列上で振り返れるようにする。

## 作業前確認

- `AGENTS.md`、`docs/lt/web-dashboard-requirements.md`、`web/csv-visualizer/README.md`、`web/csv-visualizer/assets/page-mttakao3.js`、`assets/core.js`、`assets/app.js` を読む。
- 現在のGPS鮮度、位置精度、在圏セル更新、RSRP/RSRQ/SINR、既定ネットワーク、HTTPプローブのデータ定義と鮮度判定を確認する。既存値の意味やCSV/BLE形式を推測で変えない。
- `git status` を確認し、既存の編集を上書きしない。AndroidアプリやBLEペイロード変更は、今回のUI実現に不可欠で仕様確認ができる場合以外は行わない。

## 区間データ

- まず公式に確認できる区間データを地図表示へ取り込む。初期対象は、東京都建設局が事業区間として公表する京王線の柴崎〜西調布間および相模原線の調布〜京王多摩川間の地下化区間、高尾〜高尾山口間のうち京王資料で確認できる高尾第一トンネル。
- 調布付近の公式資料: [東京都建設局の事業完了パンフレット一覧](https://www.kensetsu.metro.tokyo.lg.jp/road/pamphlet/lib/renritsukanryo)から京王線/相模原線の事業パンフレットを参照する。公式発表では柴崎〜西調布、および調布〜京王多摩川の各駅間トンネルで携帯サービスを開始したことが記載されている（[2012年の事業者発表](https://www.kddi.com/corporate/news_release/2012/0816/)）。京王電鉄も2012年に調布駅付近を地下化したと説明している（[立体交差化の説明](https://www.keio.co.jp/train/safety/security_feature/railway_crossing.html)）。
- 高尾付近の公式資料: [京王電鉄の安全報告書](https://www.keio.co.jp/assets/pdf/train/safety/security_feature/keio_2009.pdf)は、高尾線・高尾山口〜高尾駅間の「高尾第一トンネル出口付近」と記載している。
- **公式の機械可読なトンネル入口/出口緯度経度データは確認できていない。** 公式資料は事業区間、駅間、図面/報告書を示すが、現時点でアプリに直接取り込めるGeoJSON等の座標データがあると仮定しない。図面から形状を起こす場合は、駅や地形図との照合で位置を概略デジタイズし、`approximate` と不確かさを明記する。公式な区間名称・施設の存在と、こちらで推定した座標精度を混同しない。
- 設定データに区間ID、名称、路線/駅間、形状（取得できた根拠に応じて線/帯/駅間範囲）、geometry精度、位置決定方法、出典URL、確認日を持たせる。座標を資料から確認できない部分は自動判定対象にしない。出典資料の地図画像をそのまま画面素材として複製しない。
- 境界座標を信頼できる形で確定できない場合は、座標を作り話で登録しない。手動メモによる記録を残し、自動検出は「未設定」と表示する。
- 地図のGPS点を線路やトンネルへスナップしない。予定ルート概略図と実測GPS地図を混同しない。近くを歩く場合もあり得るので、乗車中/列車内と判定しない。

## 状態と表現

証拠を一つの「トンネル判定」にまとめず、公式資料由来の既知区間、GPS位置による区間近接、電波/通信の実観測を別レイヤーとして示す。

1. **地点情報: 既知の地下/トンネル区間**: 公式資料に基づく区間形状を地図上に常時「地下化区間（資料）」または「トンネル（資料）」として示す。区間データの出典と概略精度を利用者が確認できるようにする。これは現在位置や乗車を示すものではない。
2. **GPS位置: 区間付近**: 鮮度のあるGPS位置が登録済み区間の許容範囲内にある。精度円/水平精度を考慮し、境界にかかるか低精度なら「トンネル区間付近（GPS精度低下）」とする。トンネル内にいる確定表示にしない。
3. **センサー兆候: トンネルかも？**: 直前まで区間入口付近にいたGPSが鮮度切れ/欠測となり、同時刻に携帯網の観測値も取得できない、または既存の観測値から品質低下が見える場合に限り候補表示する。理由を「GPS更新なし」「在圏セル更新なし」「RSRP取得なし/低下」「HTTP失敗」など観測事実として併記する。
4. **GPS/通信の状態は別表示**: GPS欠測だけでトンネルとしない。携帯網の値が来ないだけでもトンネルとしない。在圏セルポーリング間隔の制限、権限、モデム/API制約、屋内、端末の置き場所など他の原因がある。位置履歴がなく、区間に接近した根拠もなければ「トンネルかも？」は出さない。
5. **電波がないと断定しない**: 「電波なし」「圏外」と表示するのは既存データがその状態を明確に表す場合だけ。RSRP/RSRQ/SINRがnull、在圏セル更新なし、HTTPタイムアウト、Androidのvalidated状態はそれぞれ意味が異なるため別々に表す。HTTP失敗を無線断絶と呼ばない。RSRPに独自の絶対閾値を勝手に設定しない。
6. **区間通過後**: GPS測位が再開したら「GPS測位復帰」を時刻付きで示せる。電波/HTTPの回復は各メトリクスの実観測としてグラフで示し、トンネル通過が原因と断定しない。

## UI

- `/keio-mttakao3/` のGPS地図に、確認済みのトンネル区間を「トンネル区間（参考）」として重ねる。現在状態は「付近」「かも？」「区間外/判定材料なし」を過度に場所を取らないバナー/チップで示す。
- 通信品質グラフとセル変更グラフにはトンネル候補区間を薄い帯で重ね、入口/出口の時刻が実測できた場合だけ実測境界として記録する。位置から推定した境界は「推定」と明記し、計測値自体を変えない。
- GPS欠測区間は従来どおり線をつながない。過去の最後の位置は古い値として表示し、地図上で現在地を偽装しない。
- 現在の「実測メモ: トンネル」は残してよい。手動マーカーは予測/自動検出と別の見た目・凡例にし、選択時刻とラベルを記録する。
- 一覧ワンビューを壊さず、詳細モードでも状態の根拠と時間変化を追える。既存のカード、グラフ、セル履歴、再生機能を維持する。

## デバッグと確認

- `/keio-mttakao3/#debug` で、区間へ接近→候補区間付近→GPS/通信状態の変化→測位復帰という架空シナリオを確認できるようにする。架空のGPS軌跡・電波イベントはDEBUG表示を維持し、実測値と混ぜない。
- 通常の `/#debug`、`#demo`、実測CSVの内容を不用意に変更しない。実測CSVにトンネルを示すラベルがない場合、過去データをトンネル走行として装わない。
- CSV再生スライダーを動かし、状態バナー・地図のカーソル・RSRP/RSRQ/SINR・HTTP・セル履歴が同じ時刻に揃うことを確認する。
- ライブでBLE受信が古くなった場合とCSVの欠測を区別する。サンプル時刻の改変や、欠測を0埋めする処理を入れない。

## 受け入れ条件

1. 公式資料で確認できる地下化/トンネル区間を、出典・確認日・精度区分付きの参考形状として表示できる。座標データが見つからず図面から概略化した区間は概略と明記する。
2. 地点情報、GPS位置の近接表示、GPS/携帯網/HTTPの状態が別レイヤー/別根拠として表示される。
3. GPS欠測だけ、HTTPタイムアウトだけ、セル更新なしだけではトンネル進入や圏外を断定しない。
4. 調布地下化区間と高尾線トンネル候補を地図で見分けられる。地図は参考範囲で、実測GPSをスナップしない。
5. CSV再生とBLEライブで、利用可能な測定値に応じて表示が更新される。取得していない値を作らない。
6. `#debug` の架空シナリオで状態の遷移と理由を確認できる。
7. デスクトップ一覧モードのワンビュー、詳細モード、通常ページ、セル履歴スクロール、再生操作に回帰がない。
8. ブラウザ確認、関連テスト、未確認事項を `docs/TEST_LOG.md` に記録する。

## 完了報告

変更ファイル、区間データの出典と精度、どの観測事実で各表示に遷移するか、CSV/DEBUG/BLEでの確認結果、断定できない制約と未確認事項を報告する。
