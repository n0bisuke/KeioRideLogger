# Keio Ride Logger CSV ビューア

Keio Ride Logger が保存した計測 CSV をブラウザ内で解析し、OpenStreetMap の道路・駅地図上にGPS軌跡を表示するビューアです。速度と在圏セル RSRP の時系列グラフ、セル変更も確認できます。

## 使い方

1. `web/csv-visualizer/index.html` をブラウザ（Chrome / Edge / Firefox / Safari の最新版）で開く。Mac なら Finder でダブルクリックするか、`open web/csv-visualizer/index.html` を実行する。
2. 「ファイルを選択」で CSV を選ぶ（画面にドロップしても読み込める）。
3. 軌跡の点、グラフ、セルイベントの表をクリックすると、その時刻が「選択中の時刻」に表示され、軌跡とグラフに印が付く。
4. 「表示する時間帯」のスライダーで、軌跡・グラフ・セルイベントの表示を一部の時間帯に絞れる。

軌跡図はホイールまたはピンチで拡大、ドラッグで移動でき、「全体を表示」で元に戻せます。

Node.js、アプリ用サーバー、ビルドは不要です。地図背景には OpenStreetMap の標準タイルを使います。

### GitHub Pages で開く

`main` ブランチの `web/csv-visualizer/` が変わると、GitHub Actions（`.github/workflows/pages.yml`）が自動で GitHub Pages に公開します。公開先は https://n0bisuke.github.io/KeioRideLogger/ です。

- 公開されるのは `web/csv-visualizer/` の中身だけです。CSV などのデータファイルが含まれていると、ワークフローは公開せずにエラーで止まります。
- Pages 上で開いても、CSVはブラウザ内だけで解析し、GitHubや地図サービスへアップロードしません。
- 背景地図の表示時は、ブラウザからOpenStreetMapのタイルサーバーへ地図画像をリクエストします。リクエストにより、訪問者のIPアドレスと表示範囲を示すタイル座標がOpenStreetMap側に伝わります。CSVや個々の測位点を送信するものではありません。
- 初回だけ、GitHub のリポジトリ設定で Settings → Pages → Build and deployment → Source を「GitHub Actions」にしてください。手動で公開し直すときは、Actions タブで「Deploy CSV viewer to GitHub Pages」を実行します。

## BLE ライブ受信（デモ）

Android アプリが計測中のときに、最新の値を BLE で直接受け取って表示します。インターネットは使いません。

1. Android アプリで計測を開始し、「BLE でブラウザへ共有」をオンにする（初回は「付近のデバイス」の権限を許可）。
2. このページを HTTPS（GitHub Pages）で、Web Bluetooth に対応したブラウザ（Android または PC の Chrome / Edge など）で開く。iPhone の Safari や Firefox は非対応で、ボタンが押せない状態になる。
3. 「BLE接続」を押し、一覧から端末を選ぶ（Keio Ride Logger のサービスを出している端末だけが出る）。
4. 1 秒ごとに GPS、在圏セル、セル変更候補、通信経路、HTTP 応答時間が更新される。5 秒更新がないと「古い値・更新なし」と表示する。
5. 「切断」で切れる。切断されたときは自動では再接続しないので、「再接続」を押す。

受け取ったデータ（位置、Cell ID などを含む）はこの画面に表示するだけで、保存も送信もしない。ページを閉じると消える。CSV の読み込み・地図・グラフとは独立していて、互いに影響しない。プロトコル（GATT の UUID、断片の形式、JSON の項目）は `android-app/app/src/main/kotlin/com/example/helloandroid/recording/BleProtocol.kt` の先頭のコメントにある。

## データの扱い

- CSVはブラウザのメモリ上で解析し、アップロード・送信・ブラウザへの保存はしません。
- Content-Security-Policyで、外部画像は `tile.openstreetmap.org` のみ許可します。`fetch`、フォント、フレーム等は許可していません。
- 地図を表示すると、表示領域のタイル座標が地図提供元に伝わるため、だいたいの地理範囲は分かります。正確な軌跡点やCSVそのものはリクエストに含みません。地図タイルを使わない場合は「背景地図」のチェックを外してください。
- OpenStreetMap のタイルを使うときは、地図上のクレジットを表示し、[タイル利用ポリシー](https://operations.osmfoundation.org/policies/tiles/)に従います。
- ファイル名・座標・Cell ID をコンソールに出力しません。
- 実機の CSV をこのディレクトリやリポジトリにコピーしないでください（ルートの `.gitignore` で `keio-ride-*.csv` は除外されています）。公開用のサンプルが必要な場合は、位置や識別子を削除・粗くした別ファイルを作ってください。

## 対応する CSV 形式

アプリの `CsvFormat.kt` が書き出す形式です（列の詳細はリポジトリルートの `README.md` の「実装済みの CSV 列」を参照）。

- 1 行目がヘッダー。UTF-8（BOM があっても可）、改行は LF（CRLF も可）。
- ダブルクォートで囲まれた値（カンマ、改行、`""` によるエスケープを含む）に対応。
- 必須の列は `time_utc` と `event`。ほかの列はあれば使い、なければその表示を「データなし」にする。
- 未知の列・未知のイベント種別があっても読み込みは続け、未知のイベントは件数だけ数える。

使う列とイベントは次のとおりです。

| 表示 | 使う行・列 |
|---|---|
| 時間軸 | すべての行の `time_utc`（UTC、ミリ秒）。横軸は `session_start` 行からの経過時間（ない場合は最初の行から） |
| GPS 軌跡・速度 | `gps` 行の `lat` `lon` `speed_mps`（km/h に換算）`h_accuracy_m` |
| 在圏セル RSRP | `cell` 行のうち `registered=true` の `rsrp_dbm`。同じ時刻・同じセルの重複（複数の取得経路）は 1 件にまとめる |
| 周辺セル | `cell` 行のうち `registered=false`。在圏セルとしては数えない（RSRP グラフでは任意で白抜き表示） |
| セル変更 | `cell_change` 行。`status` が `baseline`（最初の在圏セル）、`switched`（変更候補）、`indeterminate`（判定不能）。`status` がない旧形式では、`prev=none` の行を基準、それ以外を変更候補とみなす |
| 取得状況の診断 | `cell_poll` 行の `note` の `registered=` 件数、`cell_status` 行の `status` |
| 応答時間 | `http_probe` 行の `status`（成功件数のみ概要に表示） |

`time_utc` の意味: センサーとセル情報はプラットフォームの単調時刻（`elapsed_realtime_ns`）から換算した取得時刻、GPS は測位時刻です。すべての行を `time_utc` で並べます。`time_utc` が読めない行は推測で配置せず、読み飛ばした件数を表示します。

## 表示の約束ごと

- **欠測は補間しない**: GPS は 5 秒、在圏セル RSRP は 10 秒を超えて間隔が開いた区間を線で結びません。値のない行（空欄）は 0 として扱わず、描きません。
- **速度と RSRP は別のグラフ**: 単位の違う値を同じ軸に重ねません。同じ行にない値どうしを、同じ時刻の値のように並べることもしません。
- **GPS軌跡は生の測位値**: 背景に道路・駅を表示しますが、GPS位置を道路・線路へ補正していません。低精度の点（既定は水平精度 30 m 超、変更可）は白抜きで描き、精度の円も表示できます。
- **最初の在圏セルは数えない**: セル変更候補は `switched` だけを数えます。変更候補がないときは「確認できた切り替わりなし」（在圏セルは観測できた）と「在圏セルを取得できず」（`registered=true` が一度もない）を区別して表示します。API の更新間隔の制限で見逃しがありうるため、ハンドオーバーの完全な記録ではありません。
- **色だけに頼らない**: 低精度の点は白抜き、周辺セルは白抜きの円、在圏セルは塗りつぶし、変更候補はひし形と縦の破線で区別し、凡例にも示します。

## 読み込んだときに目で確認する項目

自動テストはありません。実機の CSV を読み込んだら、次の点を確認してください。

- [ ] 概要の「計測時間」「イベント総数」がアプリ画面の記録イベント数・計測時間と一致する。
- [ ] 値がない項目が「データなし」と表示され、0 や成功として表示されていない。
- [ ] 軌跡の開始・終了が実際の移動と合い、GPS が途切れた区間（トンネル、屋内）が線でつながっていない。
- [ ] 低精度の点が白抜きで描かれ、点をクリックすると時刻・速度・水平精度が表示される。
- [ ] 速度グラフの値が km/h になっている（m/s のままではない）。
- [ ] 在圏セル RSRP のグラフに、周辺セルの値が混ざっていない（「周辺セルの RSRP も表示」をオンにしたときだけ白抜きで出る）。
- [ ] 最初の在圏セルが変更候補に数えられていない。全行 `registered=false` の CSV では「在圏セルを取得できず」と表示される。
- [ ] 軌跡・グラフ・セルイベント表のどれをクリックしても、ほかの表示の選択位置が同じ時刻に移る。
- [ ] 時間帯のスライダーで、軌跡・グラフ・イベント表がそろって絞り込まれる。
- [ ] 狭い画面（スマートフォン幅）でも、ファイル選択・軌跡・グラフが操作できる。
- [ ] 壊れた行を含む CSV では、全体は表示されたまま、読み飛ばした行数が表示される。
- [ ] 空ファイルや別形式の CSV で、分かりやすいエラーが表示される。
- [ ] 背景地図がオンのとき、軌跡の位置が地図上の道路・駅とおおよそ合っている（GPS 誤差や補正なしによるずれはありうる）。右下に「© OpenStreetMap contributors」が常に表示されている。
- [ ] 「背景地図」をオフにすると地図が消え、ブラウザの開発者ツールの Network タブで `tile.openstreetmap.org` への新しいリクエストが出なくなる。
- [ ] 機内モードやオフラインで開くと、地図は「地図タイルを取得できません。軌跡は表示します。」と表示され、軌跡・グラフ・イベント表はそのまま使える。
- [ ] Network タブで、`tile.openstreetmap.org` 以外への通信（CSV のアップロードなど）が発生していない。
- [ ] （BLE）非対応ブラウザや `file://` で開くと「BLE接続」が押せず、理由が表示される。
- [ ] （BLE）選択の一覧に Keio Ride Logger の端末だけが出る。接続すると 1 秒ごとに値が変わり、Android 側の送信回数も増える。
- [ ] （BLE）アプリで共有をオフにする、または計測を止めると、ブラウザが「切断されました」になり、5 秒後には古い値と表示される。「再接続」で戻る。
- [ ] （BLE）DevTools の Network タブで、BLE の受信中に新しい通信（地図タイル以外）が発生していない。
