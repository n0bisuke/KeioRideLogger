# Keio Ride Logger Web ダッシュボード

Keio Ride Logger（Android）の計測データを、ブラウザで表示するダッシュボードです。データの入口は2つあります。

- **CSV**: アプリで保存した計測 CSV を開く（計測後の振り返り・BLE が使えないときの予備）
- **BLE ライブ**: 計測中のアプリから、BLE で最新の値を直接受け取る（インターネットを使わない）

## ページ

| パス | 用途 |
|---|---|
| `/`（`index.html`） | **移動モニター**。散歩・ドライブなど、日常の移動の記録と振り返り。路線や駅は前提にしない。参考距離と移動手段のメモ（表示用・自動判定しない）がある |
| `/keio-mttakao3/` | **Mt.TAKAO 3号 LT デモ**。京王ライナー Mt.TAKAO 3号（土休日）の発表用画面。ルート概略図（縮尺なし）、公式時刻表の予定時刻、実測メモがある |

公開先は https://n0bisuke.github.io/KeioRideLogger/ と https://n0bisuke.github.io/KeioRideLogger/keio-mttakao3/ です。2つのページは同じスクリプト（`assets/core.js`・`assets/app.js`）を使い、指標の定義、BLE と CSV の処理、地図、グラフは共通です。違いはページごとの設定（`assets/page-monitor.js`・`assets/page-mttakao3.js`）だけです。

## 使い方

1. GitHub Pages のページを開く（BLE を使う場合は HTTPS が必要。Chrome / Edge など Web Bluetooth 対応ブラウザで開く）。
2. **CSV**: 「CSV を開く」で選ぶか、画面にドロップする。
3. **BLE ライブ**: Android アプリで計測を開始し、「BLE でブラウザへ共有」をオンにしてから「BLE接続」を押し、一覧から端末を選ぶ（Keio Ride Logger のサービスを出している端末だけが出る）。1 秒ごとに更新される。
4. CSV と BLE の両方があるときは、「CSV を表示」「BLE ライブを表示」で切り替える。BLE の受信で CSV の表示や選択が上書きされることはない。ヘッダーに、どちらを表示中か、BLE の状態（受信中・受信停止・切断）、現在時刻（JST）を常に出す。
5. 地図の点、グラフ、セル変更の履歴をクリックすると、その時刻が選ばれ、地図・グラフ・カードがそろって動く。地図はホイール・ピンチで拡大、ドラッグで移動、「全体を表示」で元に戻る。
6. CSV では「表示する時間帯」のスライダーで絞り込める。BLE では直近 5〜60 分を選べる。

画面の構成: 左に GPS 軌跡の地図、右に現在のネットワーク指標（移動速度、在圏セル、電波品質、既定ネットワーク、最後の HTTP 応答時間）とセル変更の履歴、下に時系列グラフ（速度、RSRP、RSRQ と SINR/RSSNR、HTTP 応答時間、セル変更）です。CSV の場合、カードは選択中の時刻（未選択なら表示範囲の終わり）の値を示します。

**ローカルで開く場合**: スクリプトを別ファイルにしているため、`index.html` を `file://` で直接開くと、ブラウザによっては CSP でスクリプトが読み込めません。また BLE は HTTPS（または `localhost`）でしか使えません。基本は GitHub Pages で開いてください。

### GitHub Pages への公開

`main` ブランチの `web/csv-visualizer/` が変わると、GitHub Actions（`.github/workflows/pages.yml`）が自動で公開します。

- 公開されるのは `web/csv-visualizer/` の中身だけです。CSV などのデータファイルが含まれていると、公開せずにエラーで止まります。
- 初回だけ、リポジトリ設定で Settings → Pages → Source を「GitHub Actions」にしてください。手動で公開し直すときは、Actions タブで「Deploy CSV viewer to GitHub Pages」を実行します。

## データの扱い

- CSV と BLE で受け取ったデータは、ブラウザのメモリ上でだけ扱います。アップロード・送信・ブラウザへの保存（localStorage など）はしません。ページを閉じると消えます。BLE の履歴は最大 2 時間分（各系列 7,200 点まで）で、古いものから捨てます。
- CSP（Content-Security-Policy）で、スクリプトはこのサイトのものだけ、画像はこのサイトと `tile.openstreetmap.org` だけを許可し、`fetch` / XHR / WebSocket は禁止しています。
- 背景地図をオンにすると、表示範囲の地図タイルを OpenStreetMap から取得します。その際、タイル座標（おおよその表示範囲）と閲覧者の IP アドレスが OpenStreetMap に伝わります。CSV の中身、個々の測位点、Cell ID は送りません。地図は「背景地図」のチェックで切れます。地図上に「© OpenStreetMap contributors」を常に表示し、[タイル利用ポリシー](https://operations.osmfoundation.org/policies/tiles/)に従います（Referer は送信元のオリジンだけ）。
- Android 端末が行う HTTP 応答時間の計測は、端末自身の通信です。このページの通信ではありません。
- ファイル名・座標・Cell ID をコンソールに出力しません。
- 実機の CSV をこのディレクトリやリポジトリにコピーしないでください（`.gitignore` で `keio-ride-*.csv` を除外しています）。

## 表示の約束ごと

- **欠測は補間しない**: GPS は 5 秒、在圏セルの値は 10 秒を超えて途切れた区間を線で結びません。空欄の値は 0 として扱わず、描きません。速度がないときは「速度なし（0 km/h ではない）」と表示します。
- **単位の違う値は別のグラフ**: 速度 [km/h]、RSRP [dBm]、RSRQ と SINR/RSSNR [dB]、HTTP 応答時間 [ms] を別のグラフにします。HTTP 応答時間は DNS・TCP・TLS・HTTP を含む総所要時間で、無線区間の遅延や ping ではありません。HTTP の結果は点だけで、線では結びません（● 成功、▲ HTTP エラー、× タイムアウト・失敗）。
- **鮮度**: BLE は最後の受信から 5 秒を超えると「古い値・更新なし」と表示し、最新位置を灰色にします。カードは最後の測位・観測からの経過時間を示します。欠落したフレーム数も表示します。
- **セルは匿名ラベル**: 在圏セルは、セッション内で初めて現れた順に「セルA」「セルB」…と表示します。PCI などの生の値は選択中の時刻の詳細にだけ出します。周辺セル（`registered=false`）は在圏セルとして扱いません。
- **観測変更候補**: 在圏セルが変わったと観測された時点です。最初の在圏セルは「基準」で数えません。Android の更新間隔の制限で見逃しがありうるため、ハンドオーバーの確定記録ではありません。変更候補がないときは「確認できた切り替わりなし」と「在圏セルを取得できず」を区別します。
- **GPS 軌跡は生の測位値**: 道路や線路への補正はしていません。低精度の点（水平精度 30 m 超）は白抜きにします。線には縁取りを付けて、明るい地図と暗い背景（地図なし）のどちらでも見えるようにしています。
- **予定と実測を混ぜない**（LT ページ）: 時刻表の時刻は「予定」（点線）、ユーザーが追加した時刻は「実測メモ」（実線）として区別します。ルート概略図の点線の円は、選択中の時刻から時刻表で計算した予定位置で、実測位置ではありません。GPS の位置は概略図には投影しません。公式時刻表に個別の時刻がない駅の時刻は表示しません。

## LT ページの 1 画面レイアウトとルート外の表示

- `/keio-mttakao3/` は、幅 1200px 以上・高さ 760px 以上の画面（16:9 のデスクトップ、目安 1920×1080）で、ページをスクロールせずに、ヘッダー、操作、ルート概要（細い帯）、地図、主要指標、セル変更の履歴、時系列グラフが収まるように配置します。地図は残りの高さいっぱいに広がり、右の指標列は収まらない分だけ列の中でスクロールします。説明や「データの扱い」「この図について」は折りたたんでいます。文字や凡例は小さくしていません。小さい画面では、これまでどおり縦にスクロールします。移動モニター（`/`）は従来のスクロールする配置です。
- **ルート外の表示**: 地図の GPS 位置は、実際の位置をそのまま描きます。ルート帯には、GPS の位置が予定ルート（新宿〜高尾山口の主要駅の公開位置を結んだ概略線）から 2 km 以上離れていれば「ルート外で動作確認中（予定ルートから約 X km）」、近ければ「予定ルート付近（乗車中かどうかは判定しません）」、位置がなければ「GPS 位置なし」と出します。「乗車中」「走行中」とは表示しません。概略線は判定のためだけに使い、位置を線路へ寄せることはしません。

## 指標カードの説明

在圏セル・RSRP・RSRQ・SINR/RSSNR のカードには、値の下に日本語の一行説明を常に表示します（在圏セル「端末が現在使っている携帯基地局のセル」、RSRP「基準信号の強さ（0 に近いほど強い）」、RSRQ「受信品質の目安（干渉などの影響を含む）」、SINR/RSSNR「信号と雑音・干渉の比（高いほど信号が明瞭）」）。これらは端末が観測した無線の指標で、通信速度や体感品質そのものではないことをカードの下に記しています。取れない指標は「未取得」と表示し、0 にしません。

## 補助センサー（加速度・気圧）

時系列の下の「補助センサー（加速度・気圧）」を開くと、CSV の `accel`（x・y・z）と `pressure`（hPa）を同じ時間軸で表示します（初期状態は閉じています）。加速度は重力を含む端末座標系の値で、列車の進行方向や加減速とは限りません。気圧は補助観測で、標高には換算しません。20 Hz の加速度は、描画するときだけ 1 ピクセル幅ごとの最小・最大に間引きます。記録頻度は CSV の `sensor_rate` 行の実測値を示し、端末にセンサーがなければ「この端末では未取得」と出します。BLE ライブはまだセンサーの値を送っていないため、「BLE ライブでは未対応（CSV のみ）」と表示します。

**トンネル区間は未登録です。** 要件では、調布付近の地下区間と高尾〜高尾山口間のトンネルを地図に参考表示することになっていますが、入口・出口の位置を資料や地図で確認してから登録する方針のため、確認前の位置は入れていません。

## 速度キャラクター

両ページの右上に、GPS 速度に合わせて姿が変わるオリジナルの 8bit 風ムササビを表示します。乗り物を判定するものではなく、速度に合わせた演出です。

- 判定は Android アプリ（`SpeedState.kt`）と同じ規則を `assets/core.js` の `SpeedClassifier` に移植したものです。速度帯は 停止 [0,1)・ゆっくり歩き [1,3)・普通歩き [3,6)・走る [6,15)・自転車くらい [15,30)・車くらい [30,90)・京王ライナー高速域 [90,∞) km/h（60 km/h は車くらい）。直近 5 秒の有効な速度の中央値を使い、境界は max(0.5 km/h, 境界値の 10%) を越えたときに切り替えます。水平精度 30 m 超、速度なし、測位なし、5 秒を超えて更新がないときは「GPS待ち」「GPS更新なし」「精度不足」「速度不明」と表示し、0 km/h とは区別します。「京王ライナー高速域」は演出上の速度帯で、高速道路の車も入りえます。
- 判定する時刻は、CSV では選択中の時刻（未選択なら表示範囲の終わり）、BLE では最後に受信した端末時刻に受信からの経過時間を足した時刻です。どちらも直前 60 秒の測位を順に流して判定するので、同じデータなら CSV と BLE、2 つのページで同じ状態になります。（Android アプリは計測開始から連続して判定するため、境界のすぐ近くの速度が長く続いた場合だけ、ヒステリシスの起点の違いで帯が異なることがあります。）
- **画像の正本は Android 側**の `android-app/app/src/main/res/drawable-nodpi/glider_speed_sheet.png` です。GitHub Pages は `web/csv-visualizer/` しか公開しないため、同じファイルを `assets/glider_speed_sheet.png` に同梱しています。**更新するときは**、Android 側を差し替えたあと `cp android-app/app/src/main/res/drawable-nodpi/glider_speed_sheet.png web/csv-visualizer/assets/` でコピーし、`cmp` で同じことを確認してください。4 列 × 2 行のうち左上から 7 コマを使い、右下の空きコマは使いません。スムージングを切って描画し、縦横比を保ちます。画像を読み込めないときは文字だけを表示します。

## 対応する CSV 形式

アプリの `CsvFormat.kt` が書き出す形式です（列の詳細はリポジトリルートの `README.md` を参照）。1 行目がヘッダー、UTF-8（BOM 可）、LF（CRLF 可）、ダブルクォートの値（カンマ・改行・`""`）に対応します。必須の列は `time_utc` と `event` です。未知の列・イベントがあっても読み込みを続けます。`time_utc` が読めない行は推測で配置せず、読み飛ばした件数を表示します。`cell_change` に `status` がない旧形式では、`prev=none` の行を基準、それ以外を変更候補とみなします。

BLE のプロトコル（GATT の UUID、断片の形式、JSON の項目）は `android-app/app/src/main/kotlin/com/example/helloandroid/recording/BleProtocol.kt` の先頭のコメントにあります。

## 目で確認する項目

自動テストはリポジトリに含めていません（開発時に Node と jsdom で、架空のデータを使って確認しています）。実機のデータで次を確認してください。

- [ ] `/` と `/keio-mttakao3/` を直接開け、再読み込みしても表示され、互いのリンクで行き来できる。
- [ ] CSV を開くと、ヘッダーに「表示: CSV」と出て、地図・カード・履歴・グラフが表示される。値のない項目は「データなし」で、0 や成功になっていない。
- [ ] 地図・グラフ・履歴のどれをクリックしても、ほかの表示が同じ時刻に移る。時間帯のスライダーでそろって絞り込まれる。
- [ ] GPS が途切れた区間（トンネル、屋内）が線でつながっていない。低精度の点が白抜きになっている。
- [ ] 背景地図がオンのとき、右下に帰属表示があり、軌跡が明るい地図の上でも見える。オフにすると、DevTools の Network タブで `tile.openstreetmap.org` への新しいリクエストが出ない。オフラインでは「地図タイルを取得できません」と出て、軌跡とグラフは使える。
- [ ] Network タブで、`tile.openstreetmap.org` とページ自身以外への通信が発生していない（BLE 受信中も同じ）。
- [ ] BLE: 非対応ブラウザでは「BLE接続」が押せず、理由が出る。接続すると 1 秒ごとに更新される。CSV を表示中に BLE を受信しても、CSV の表示は変わらない。共有をオフにするか計測を止めると、5 秒後に「古い値」、切断で「切断されました」と出て、「再接続」で戻る。
- [ ] BLE: 同じ HTTP 計測の結果が、毎秒新しい点として増えない。
- [ ] LT ページ: 予定時刻の線（11:00・11:06・11:45 JST）が、グラフ上で正しい間隔に並ぶ（6 分と 39 分）。実測メモを追加すると実線で出る。
- [ ] 発表会場のプロジェクターで、文字・カード・グラフが読める。狭い画面でも操作できる。
